# CapCut ドラフト編集

CapCut デスクトップ版(Mac)は、プロジェクトを `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/<プロジェクト名>/` に **暗号化されていないJSON** で保存する(8.9.0 で確認)。このJSONを直接書けば、画面を操作せずに「素材を並べた・BGMとタイトルが付いた」プロジェクトを作れて、ユーザーがCapCutで開いて仕上げられる。

## 先に知っておくこと(ここで時間を溶かさないために)

- **私はCapCutの画面を触れない。** 許されるのはファイル生成だけ。書き出し(エクスポート)・細かい見た目の調整はユーザーの作業。最初にそう伝え、代わりにこの方法を提案する。
- **作業先はユーザーのMac。** コンテナ側にはCapCutもプロジェクトもない。クラウドセッションなら `list_computer_folders` → `request_computer_folder` で素材フォルダに接続する(信頼確認 `confirm_repository_trust` が先に要ることがある)。接続後は Bash/Read/Write に `_host`(ツール一覧に出るホスト名。表示名の `computer_name` とは綴りが違うことがある)を付ける。再起動で切れたら同じ手順で再接続する。
- **ffmpeg は入っていないことが多い。** 動画の長さ・解像度は MP4 の `moov` ヘッダーから直接読む(`measure_clips.py`)。`mdls`(Spotlight)や `afinfo` は未インデックス/遅いので当てにしない。
- **iCloud に退避された動画(`ls -lO` に `dataless`)が混ざる。** 読むとタイムアウトする。`brctl download` で実体を落としてから読む。**全部落とすとMacの空き容量を食う**ので、先に `df -h` と `ls -lO` で本数・合計GBを数えて、足りるかユーザーに伝える。長さの推定は容量比でできるが誤差が大きいので、ドラフトに入れる長さは必ず実測値にする(ずれると映像が止まる/黒くなる)。
- **映像の中身は見えない。** 「場面」の区切りは撮影時刻のギャップ(昼食・移動・翌日)で決める。場所名は分からないので、ラベルは撮影日時を仮文字にして、後から差し替えられると伝える。
- **CapCut は終了してから書き込む。** 起動中は `root_meta_info.json`(プロジェクト一覧)や開いているプロジェクトを上書きされ、作ったものが消えたり編集が失われる。`ps aux | grep CapCut` で確認する。

## 手順

### 0. ヒアリング(短く)
- 素材フォルダ、目標の尺(例: 10〜12分)、分割するか(何本・どこで)、**見本にするプロジェクト名**。
- 見本の名前が曖昧なとき(例: 「1115」は日付かもしれない)は、実際に中身を調べる: 各プロジェクトの `Timelines/*/draft_info.json` の `materials.audios / texts / material_animations` の数を一覧にし、BGMと文字が入っているものを候補として示して選んでもらう。**中身が空のプロジェクトを見本にしない。**
- 見本のBGM・フォント・アニメーション設定は `draft_info.json` から読んで、何を再現するか(曲名、フォント、縁取り/影、タイプライター等)をユーザーに言葉で見せる。

### 1. 素材を測る → `scripts/measure_clips.py`
```bash
python3 measure_clips.py --dir <素材フォルダ> --out /tmp/clips_meta.json
```
iCloud退避分は順にダウンロードして実測する(再開可能)。合計尺と本数を出して、**前に推定した数字と違っていたら正直に訂正する。** バックグラウンドで走らせたときは通知が来ないので、ログを読んで進捗を確認する。

### 2. 全クリップ入りプロジェクトを作る → `scripts/build_all_clips.py`
```bash
python3 build_all_clips.py --clips-dir <素材フォルダ> --meta /tmp/clips_meta.json --name <新プロジェクト名> --base <動画1本だけの小さな既存プロジェクト>
```
ファイル名順(=撮影順)に1本のタイムラインへ並べる。同名の `x`, `x(1)`, `x(2)` が混ざることがあるので、重複の可能性と0.3秒の極短クリップをユーザーに知らせる。既存プロジェクトは触らず、`root_meta_info.json` に1件足すだけ(バックアップ `.bak_claude`)。ユーザーはCapCutを開いてカットする。ここでユーザーの作業を待つ。

### 3. カット後に分割+装飾 → `scripts/suggest_scenes.py` と `scripts/split_decorate.py`
カット後に「`mm:ss` までと、それ以降で2本に」のような指示が来る。
1. タイムライン秒から、その位置のクリップ境目(セグメント番号)を探す。撮影ギャップが大きい境目なら自然。
2. `suggest_scenes.py --project <カット済み> --ranges 0:66 66:` で各動画の4場面の境目を提案させ、ユーザーに見せる。
3. `split.json` を書いて `split_decorate.py --config split.json` を実行。各動画に **冒頭のタイトル(タイプライター風)+タイピング効果音+場面ごとに1曲(曲数=場面数、長い場面は同じ曲を頭から繰り返し、場面終わりは1.5秒フェードアウト)** が付く。曲の音量は見本のまま。
- タイトル文は日付+仮の見出し(例: 「2026年8月23日〜24日 / 旅行 前編」)。行き先が分かれば差し替える。
- 元のカット済みプロジェクトは変更しない(新しい名前で2本作る)。

### 4. 場所ラベル → `scripts/add_labels.py`
「時刻が大きく開いた箇所ごとに左上へ文字+タイプライターを残して」という依頼向け。`--gap-min 30` が既定。見本の左上ラベルと同じ位置・サイズ・影・タイプ音で、次の区間の頭まで出しっぱなしにする。**ユーザーがカット後に編集・保存した可能性があるので、再生成せず現状に追記する**(バックアップ `.bak_labels`)。実名は `--labels-json` で渡せる。

### 5. 検証と引き渡し → `scripts/verify_project.py`
```bash
python3 verify_project.py <プロジェクト名...>
```
ID重複、参照切れ、孤立素材、素材ファイルの存在、映像トラックの連続性、一覧登録を確認する。**CapCutで実際に開いて確認したわけではない** ことを正直に伝え、開けない/一覧に出ないときはCapCutを一度終了して開き直す→それでもだめなら連絡してもらう、と案内する。

## 報告のしかた
- 作ったプロジェクト名、尺、カット数、場面の境目(mm:ss)、BGMの割り当て表を短くまとめる。
- 仮のもの(タイトル文、ラベル文字)と、推定でしか決められなかったもの(場面の境目は撮影時刻ベース)を明示し、直し方(CapCutで編集 or 私に伝える)を添える。
- ユーザーが編集済みのプロジェクトに書き込んだ場合は、バックアップの場所を言う。

## 壊れやすい点
詳しい構造・落とし穴は `references/format-notes.md`。CapCutのバージョンが上がるとドラフト形式が変わり(暗号化されることもある)、このスキルの方法が使えなくなる可能性がある。その場合は既存プロジェクトの `draft_info.json` が平文JSONか最初に確認し、読めなければ素直に「この版では直接生成できない」と伝えて、手順の案内(CapCut画面での操作)に切り替える。
