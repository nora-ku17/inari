# バレットジャーナル

デイリー / マンスリー / フューチャーログ、やりたい100、買いたいもの、行きたい場所、株売買記録。
公開URL(GitHub Pages): https://nora-ku17.github.io/inari/bujo/ (設定により https://nora-ku17.github.io/inari/ )

ホーム画面に追加すると、アプリとして全画面で使えます(オフラインでも開けます)。

## 端末どうしで同期する(会社PC・自宅PC・スマホ)

「かぞく手帳」と同じ Firebase プロジェクト・同じアカウントを使います。

1. **ルールを更新(最初の1回だけ)**: Firebase コンソール → Firestore Database → ルール に、
   [`kazoku/firestore.rules`](../kazoku/firestore.rules) の内容をすべて貼り付けて「公開」
   (かぞく手帳のルールはそのまま残り、バレットジャーナル用の設定が足されます)
2. アプリの「設定」タブ → 「端末どうしの同期」
   - 設定: `firebaseConfig` を貼り付け(かぞく手帳の設定と同じもの)。
     2台目以降は、すでに同期している端末で「他の端末用の設定リンクをコピー」して、そのリンクを開くだけ
   - ログイン: かぞく手帳で作ったメール・パスワードで「ログイン」(なければ「はじめて」で作成し、確認メールのリンクを開く)
3. 以降、同じアカウントでログインした端末どうしで、データが自動で共有されます

最初にログインしたとき、その端末にすでにあるデータとクラウドのデータは「合体」します(消えません)。

### 会社PCなど共用の端末で
- 使い終わったら「ログアウト」→ 「この端末のデータも消す」を選べます(クラウドのデータは消えません)。
- 会社のネットワークが Google のサーバー(`*.googleapis.com`)をブロックしていると同期できません。
  その場合は「設定」タブに「同期エラー」と出ます。
- 株売買の記録もクラウド(あなたのFirebase)に保存されます。会社のルールで問題ないか確認してください。

## セキュリティ
- 読み書きできるのは、メール確認済みで、自分のデータだけです(`kazoku/firestore.rules`)。
- 同期・JSON読み込みで受け取ったデータは、表示する前にすべて検査します(`storage.js` の `normRecord`)。
- `firebaseConfig`(apiKey など)は公開されても問題ない設計の値です。データはルールで守られます。

## ファイル
| ファイル | 内容 |
| --- | --- |
| `index.html` / `style.css` / `app.js` | アプリ本体(ビルド不要) |
| `storage.js` | 端末内の保存と、受け取ったデータの検査 |
| `sync.js` | Firebase による同期。項目を1件ずつ保存するので、別々の端末で別々の項目を追加しても上書きし合いません |
| `vendor/firebase-10.14.1.js` | Firebase SDK(かぞく手帳と同じファイル) |
| `sw.js` / `manifest.webmanifest` / `icons/` | アプリ化(PWA)・オフライン対応 |

ファイルを更新したときは、`sw.js` の `VERSION` を上げると、各端末に新しい版が届きます。
